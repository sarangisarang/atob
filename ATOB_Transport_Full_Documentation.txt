5. Domain Model
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

5.1 Enums

  TransportType:
    LIGHT | TRUCK | TRAILER

  ShippingStatus (canTransitionTo + isTerminal):
    CREATED → ASSIGNED → PICKUP_IN_PROGRESS → PICKED_UP → IN_TRANSIT → DELIVERED
    CREATED/ASSIGNED → CANCELLED
    PICKUP_IN_PROGRESS/PICKED_UP/IN_TRANSIT → FAILED
    Terminal (no further transitions): DELIVERED, CANCELLED, FAILED

  VehicleType:
    CAR | VAN | TRUCK | TRAILER

  CargoType:
    GENERAL_GOODS | VEHICLE | CONSTRUCTION_MATERIAL | EQUIPMENT | OTHER

  OrderStatus (TransportOrder):
    Pending → Processing → WaitingCarrier → Shipped → Delivered | Cancelled

5.2 Entities

  Carrier (= Driver in current model)
    id, email, firstName, lastName, password, address, postcode, city, phone
    ⚠️ Carrier ეს არის driver — future refactor: Carrier=company, Driver=person

  Customer
    id, email, firstName, lastName, password, address, postcode, city, phone

  Vehicle
    id, plateNumber, vehicleType, maxWeightKg, maxVolumeM3, active, carrier(FK), createdAt

  Location
    id, address, postcode, city, phone

  Product
    id, productName, productDesc, hasImage, imageUrl, stock, carrier(FK), images(BYTEA)

  TransportOrder
    id, orderId, orderNo, orderDate, shippingDate, deliveredDate, orderStatus,
    shippingFrom(FK Location), shippingTo(FK Location), customer(FK), product(FK)

  Shipping  ← CORE ENTITY
    id, transportType, shippingStatus,
    deliveryStartAt, deliveryEndAt,
    trackingLatitude, trackingLongitude,
    notes, updatedAt,
    carrier(FK — driver), vehicle(FK), order(FK TransportOrder)

  Cargo
    id, shipping(FK), name, description, cargoType,
    weightKg, lengthCm, widthCm, heightCm,
    vin (vehicle cargo only), plateNumber, quantity

  TrackingEvent
    id, shipping(FK), carrier(FK), latitude, longitude, speed, recordedAt

  ChatConversation
    id, customerId, driverId, shippingId (UNIQUE), active, createdAt, updatedAt

  Message
    id, conversation(FK), senderId, senderRole(CUSTOMER|DRIVER), content, sentAt, read

  ServiceUser
    id, username, password (bcrypt or noop)

  UserRole
    id, roleName (ROLE_ADMIN|ROLE_DRIVER|ROLE_CUSTOMER), user(FK)

6.2 Shippings — FROZEN API CONTRACT
  GET    /api/shippings                         role-filtered list
    params: ?page=0&size=20 (max size=100, sorted by updatedAt DESC)
  GET    /api/shippings/{id}                    ownership-checked
  GET    /api/shippings/by-order/{orderId}      OrderDetailScreen lookup
  POST   /api/shippings                         [ADMIN] create
  PATCH  /api/shippings/{id}/assign-driver/{driverId}   [ADMIN]
  PATCH  /api/shippings/{id}/assign-vehicle/{vehicleId} [ADMIN]
  PATCH  /api/shippings/{id}/start-pickup       [DRIVER — own shipment]
  PATCH  /api/shippings/{id}/picked-up          [DRIVER — own shipment]
  PATCH  /api/shippings/{id}/in-transit         [DRIVER — own shipment]
  PATCH  /api/shippings/{id}/deliver            [DRIVER — own shipment]
  PATCH  /api/shippings/{id}/cancel             [ADMIN]
  PATCH  /api/shippings/{id}/fail               [ADMIN]
  POST   /api/shippings/{id}/tracking           [DRIVER — own, rate limited: 1/10s]
    body: {latitude, longitude, speed?}
    returns: 429 Too Many Requests if exceeded
  GET    /api/shippings/{id}/tracking           [ALL — ownership-checked]
  GET    /api/shippings/{id}/cargo              [ALL — ownership-checked]
  POST   /api/shippings/{id}/cargo              [ADMIN]
  DELETE /api/shippings/cargo/{cargoId}         [ADMIN]

Ownership (enforced in ApiShippingController):
  Admin   → sees everything
  Driver  → shipping.carrier.email == principal.name
  Customer→ shipping.order.customer.email == principal.name

ShippingStatus.isTerminal() blocks:
  - assign driver/vehicle to terminal shipment
  - add cargo to terminal shipment
  - any status update on terminal shipment

GPS Rate Limit (TrackingRateLimiter, Bucket4j):
  - Max 1 GPS update per 10 seconds per driver
  - Returns 429 Too Many Requests if exceeded
  - In-memory token bucket — no Redis needed

16. Known Issues / Gotchas
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Tunnel URL
   - localhost.run anonymous changes URL every restart
   - FIX: edit frontend/src/config.js only — no APK rebuild needed

2. Hibernate naming: maxVolumeM3
   - SpringPhysicalNamingStrategy → max_volumem3 (no _ before digit 3)
   - FIX: @Column(name = "max_volume_m3") on Vehicle.maxVolumeM3

3. Lazy loading
   - Carrier in Vehicle: @JsonIgnoreProperties({"hibernateLazyInitializer","handler"})
   - Vehicle in Shipping: FetchType.EAGER (prevents proxy serialization error)
   - Cargo.shipping: LAZY — CargoResponseDTO.from() handles it safely

4. DB reset
   docker exec tracktransporter-postgres-1 psql -U atob -d atobapp \
     -c "DROP SCHEMA public CASCADE; CREATE SCHEMA public;"
   Then restart backend — Flyway re-runs V1+V2+seed

5. Carrier entity naming
   - Carrier in DB = driver person (not a company)
   - ShippingResponseDTO correctly exposes: carrierId / driverFirstName / driverLastName
   - Never expose Carrier entity directly — use DTO

6. GPS rate limit in-memory
   - TrackingRateLimiter uses ConcurrentHashMap — resets on backend restart
   - Production: replace with Redis-backed Bucket4j

7. Admin password

   - DELETED — any screen using /shipping/** will get 404
   - All screens migrated to /api/shippings/**
   - client.js legacy aliases point to new routes
