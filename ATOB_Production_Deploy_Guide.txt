  24/24 PASS (localhost-ზე ვერიფიცირებული)

  1.  Admin login → 200
  2.  Driver1 login → 200
  3.  Driver2 login → 200
  4.  Customer login → 200
  5.  Admin sees all shippings
  6.  Driver1 sees only own shipment
  7.  Customer sees own shipment
  8.  Driver2 blocked from Driver1 shipment → blocked
  9.  Customer2 blocked from Customer1 shipment → blocked
  10. Admin assigns vehicle + driver → ASSIGNED
  11. ASSIGNED → PICKUP_IN_PROGRESS
  12. PICKUP_IN_PROGRESS → PICKED_UP
  13. PICKED_UP → IN_TRANSIT
  14. IN_TRANSIT → DELIVERED
  15. Invalid: ASSIGNED → DELIVERED → blocked
  16. Terminal: DELIVERED → CANCELLED → blocked
  17. Driver GPS for own shipment → 200
  18. GPS rate limit (2nd request <10s) → 429
  19. Driver blocked from other's GPS
  20. Customer reads own tracking → 200
  21. Customer2 blocked from other's tracking
  22. /api/shippings/by-order/1 → 200
  23. /api/vehicles?page=0&size=10 → 200
  24. /api/shippings?page=0&size=5 → list

STEP 1 — VPS შექმნა
─────────────────────────────────────────────────────────────────

  სამართავი: https://console.hetzner.cloud
  Plan:       CX22 — 4 vCPU, 4GB RAM — €5/month
  OS:         Ubuntu 22.04 LTS
  Region:     Nuremberg (EU) ან Helsinki

  შექმნის შემდეგ:
  - SERVER_IP-ს ჩაინიშნე
  - DNS A record: api.your-domain.com → SERVER_IP
  - DNS propagation: 5–15 წუთი

  Verify DNS:
    nslookup api.your-domain.com


STEP 2 — ფაილების VPS-ზე ატვირთვა
─────────────────────────────────────────────────────────────────

  ლოკალური machine-იდან:

    scp -r /home/python/Desktop/TrackTransporter/deploy \
        root@SERVER_IP:/opt/atob-transport/

    scp -r /home/python/Desktop/TrackTransporter/backend \
        root@SERVER_IP:/opt/atob-transport/

    scp -r /home/python/Desktop/TrackTransporter/scripts \
        root@SERVER_IP:/opt/atob-transport/


STEP 3 — .env კონფიგურაცია სერვერზე
─────────────────────────────────────────────────────────────────

  ssh root@SERVER_IP
  cd /opt/atob-transport/deploy

  cp .env.template .env
  chmod 600 .env
  nano .env

  შეავსე:
    DB_NAME=atobapp
    DB_USER=atob_user
    DB_PASSWORD=<strong_random_password>
    API_DOMAIN=api.your-domain.com
    ALLOWED_ORIGINS=https://your-domain.com
    JWT_SECRET=<64_char_random_string>

  პაროლის გენერაცია:
    openssl rand -base64 32    ← DB password
    openssl rand -hex 64       ← JWT secret

  კრიტიკული: .env ᲐᲠᲐᲡᲝᲓᲔᲡ არ commit-ოს Git-ში!


STEP 4 — Automated Setup გაშვება
─────────────────────────────────────────────────────────────────

  ssh root@SERVER_IP

  bash /opt/atob-transport/deploy/setup-vps.sh \
      api.your-domain.com \
      admin@your-email.com

  სკრიპტი აკეთებს:
  1. Docker + Docker Compose installation
  2. Firewall (80, 443, SSH)
  3. HTTP-only config-ით სერვისების გაშვება
  4. Let's Encrypt SSL certificate მოღება
  5. HTTPS config-ზე გადართვა
  6. Daily backup cron (03:00)

  ხანგრძლივობა: ~5–10 წუთი


STEP 5 — Manual Setup (თუ automated-ი ვერ მუშაობს)
─────────────────────────────────────────────────────────────────

  5a. HTTP-only-ით გაშვება:
    cd /opt/atob-transport/deploy
    cp nginx/conf.d/atob.conf nginx/conf.d/atob.conf.bak
    rm nginx/conf.d/atob.conf
    docker compose -f docker-compose.prod.yml up -d --build

  5b. SSL certificate:
    docker compose -f docker-compose.prod.yml run --rm certbot \
        certonly --webroot \
        -w /var/www/certbot \
        -d api.your-domain.com \
        --email admin@your-email.com \
        --agree-tos --no-eff-email --non-interactive

  5c. HTTPS-ზე გადართვა:
    mv nginx/conf.d/atob.conf.bak nginx/conf.d/atob.conf
    rm nginx/conf.d/atob-init.conf
    sed -i 's/api.YOUR-DOMAIN.com/api.your-domain.com/g' \
        nginx/conf.d/atob.conf
    docker compose -f docker-compose.prod.yml exec nginx nginx -s reload


STEP 6 — Verification
─────────────────────────────────────────────────────────────────

  # HTTPS health check
  curl -i https://api.your-domain.com/auth/me
  # Expected: HTTP 401 (protected — backend is alive)

  # Admin login
  curl -u "admin:1234" https://api.your-domain.com/auth/me
  # Expected: {"username":"admin","role":"ADMIN",...}

  # SSL check
  curl -vI https://api.your-domain.com/auth/me 2>&1 | grep "SSL\|certificate\|expire"

4. Backup — Daily კოპია
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Manual backup:
  bash /opt/atob-transport/deploy/backup.sh

  შედეგი:
    /opt/atob-transport/deploy/backups/atobapp_2026-05-30.sql.gz

List backups:
  ls -lh /opt/atob-transport/deploy/backups/

Restore from backup:
  bash /opt/atob-transport/deploy/restore.sh \
      /opt/atob-transport/deploy/backups/atobapp_2026-05-30.sql.gz

  (asks for "yes" confirmation — drops DB and restores)

Automatic cron (03:00 daily):
  0 3 * * * /opt/atob-transport/deploy/backup.sh >> /var/log/atob-backup.log 2>&1

Retention: 14 days (older files auto-deleted)

5. Docker Commands (VPS-ზე)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  cd /opt/atob-transport/deploy

  # ყველა სერვისის გაშვება
  docker compose -f docker-compose.prod.yml up -d

  # გაჩერება
  docker compose -f docker-compose.prod.yml down

  # Logs
  docker compose -f docker-compose.prod.yml logs -f backend
  docker compose -f docker-compose.prod.yml logs -f nginx

  # Backend restart only
  docker compose -f docker-compose.prod.yml restart backend

  # Code change-ის შემდეგ rebuild
  docker compose -f docker-compose.prod.yml up -d --build backend

  # Container status
  docker compose -f docker-compose.prod.yml ps

7. Docker Compose Services
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  postgres
    image: postgres:15-alpine
    volume: pgdata (persistent)
    network: internal only (not exposed publicly)
    healthcheck: pg_isready

  backend
    build: backend/Dockerfile (multi-stage)
    env: SPRING_PROFILES_ACTIVE=prod + DB vars
    depends_on: postgres (healthy)
    network: internal only
    port: 8080 (internal)

  nginx
    image: nginx:1.25-alpine
    ports: 80:80, 443:443 (public)
    volumes: conf.d, certbot certs, acme challenge
    networks: internal + external

  certbot
    auto-renewal every 12 hours
    volumes: same certbot dirs as nginx

8. application-prod.properties
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  spring.datasource.url=jdbc:postgresql://${DB_HOST:postgres}:5432/${DB_NAME}
  spring.datasource.username=${DB_USER}
  spring.datasource.password=${DB_PASSWORD}
  spring.jpa.hibernate.ddl-auto=validate
  spring.jpa.open-in-view=false
  spring.flyway.locations=classpath:db/migration   ← no seed data!
  spring.sql.init.mode=never
  logging.level.root=WARN

  განსხვავება dev-ისგან:
  - DB host არის "postgres" (Docker service name)
  - Seed data არ ჩაიტვირთება (db/dev გამოტოვებულია)
  - Hibernate validate mode (არ ქმნის ცხრილებს)
  - Credentials env-var-ებიდან

  HTTPS (port 443):

    Max upload: 20MB
    proxy_pass: http://backend:8080
    Timeout: 30s

  Headers forwarded to backend:
    Host, X-Real-IP, X-Forwarded-For, X-Forwarded-Proto

  # Start all services
  docker compose -f docker-compose.prod.yml up -d

  # View backend logs
  docker compose -f docker-compose.prod.yml logs -f backend

  # Manual backup
  bash /opt/atob-transport/deploy/backup.sh

  # Restore backup
  bash /opt/atob-transport/deploy/restore.sh backups/atobapp_2026-05-30.sql.gz

  # Production smoke test
  BASE_URL=https://api.domain.com bash scripts/smoke-phase1.sh

  docker compose -f docker-compose.prod.yml run --rm certbot renew

  # APK build
  cd frontend/android && ./gradlew assembleRelease

  docker exec atob-postgres psql -U atob_user -c \
